# edge: the router for published apps

A Cloudflare Worker that serves every published app at `{name}.bytauai.pro`.
A request's hostname picks a routing record in KV, the record names an
immutable prefix in R2, and the path picks a file under it. It holds no secrets
and never calls tau, so published apps keep serving when tau's server is down.
Design: `doc/PUBLISHING.md` (D3, C4, Phase 2).

```
src/sites.ts      path, slug, content-type and cache rules (ported from server/src/lib/sites.ts)
src/badge.ts      the "Built with tau" badge, as the edge adds it
src/badgeSource.ts  generated by `bun run sync-badge`; do not edit
src/serve.ts      the handler: record lookup, serving, SPA fallback, suspended page
src/index.ts      the Worker entry (turns a storage failure into a plain 503)
```

The rules exist here and in the server, and `server/test/api/siteEdgeDrift.test.ts`
fails if they differ. Change a rule in both. If the badge script changes, run
`bun run sync-badge`.

## Working on it

```
bun install
bun run typecheck
bun test test/
bun run dry-run        # bundles it; needs no account
bun run dev            # the real Worker runtime, with local R2 and KV
```

To try it locally, seed the local stores (add `--persist-to <dir>` to all three
commands so they share state):

```
bunx wrangler r2 object put tau/tau/sites/u1/p1/d1/index.html --local --file index.html --content-type "text/html; charset=utf-8"
bunx wrangler kv key put --binding ROUTES --local "host:my-app.bytauai.pro" '{"projectId":"p1","slug":"my-app","prefix":"tau/sites/u1/p1/d1","showBadge":true,"suspended":false}'
bun run dev
curl -H "Host: my-app.bytauai.pro" http://127.0.0.1:8787/
```

## Going live

Needs the domain active on Cloudflare (SSL mode Full (strict)) and an API token
with Workers Scripts: Edit, Workers KV Storage: Edit and, for the route and
DNS, Workers Routes: Edit and DNS: Edit on the zone.

1. `export CLOUDFLARE_API_TOKEN=… CLOUDFLARE_ACCOUNT_ID=…`
2. `bunx wrangler kv namespace create ROUTES`, then put the id it prints in
   `wrangler.toml` (replacing `REPLACE_WITH_KV_NAMESPACE_ID`).
3. `bun run deploy`. The Worker is deployed and receives nothing yet, because
   no route is set.
4. In Cloudflare DNS add a proxied wildcard record: type `AAAA`, name `*`,
   value `100::`. It only makes Cloudflare answer for every subdomain; there is
   no origin.
5. In `wrangler.toml` uncomment `routes`, and `bun run deploy` again.
6. On the API server set `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_KV_NAMESPACE_ID`
   and `CLOUDFLARE_API_TOKEN` (the token needs only Workers KV Storage: Edit
   there), then `SITES_DOMAIN=bytauai.pro` and `SITES_PATH_MODE=redirect`, and
   restart. The reconciler runs at boot and writes a record for every live
   site; from then on tau pushes one after every publish, rollback, take
   offline, suspension, plan change and project delete.
7. Check: publish an app and open `https://{name}.bytauai.pro`; stop the API
   server and reload (it must still load); open an unknown subdomain (404).

`SITES_DOMAIN` changes every address shown to users, so set it only after step 5.

## Limits to watch (Cloudflare free plan)

100,000 Worker requests a day across all apps, 100,000 KV reads and 1,000 KV
writes a day. A record is read once per request (cached at the edge for 60
seconds, which is also the longest a publish takes to show) and written once
per change; the reconciler lists and writes only what differs.
